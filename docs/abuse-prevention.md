# 业务接口滥用防护

本机制保持扫码登记与重复挑战，限制突发请求和新记录创建速率。它不验证手机号/邮箱的实际控制权，不提供验证码，也不能完全阻止分布式机器人。

## 应用令牌桶

`quiz.rate_limits` 的策略由所有Web进程通过数据库共享。每次操作消耗一个令牌，余额按经过时间补充且不超过容量。

| 策略 | 容量 | 补充 |
| --- | ---: | --- |
| 浏览器登记/恢复 | 8 | 8次/分钟 |
| 同活动编号登记/恢复 | 6 | 6次/分钟 |
| 同活动来源IP新增身份 | 100 | 120个/分钟 |
| 同活动新增身份 | 200 | 1,000个/小时 |
| 同参与者新建答卷 | 10 | 1份/分钟 |
| 同活动新建答卷 | 200 | 120份/分钟 |

浏览器标识来自CSRF中间件验证的Cookie。编号规范化后计数，换IP/浏览器不重置编号额度。恢复不扣新增身份额度；返回已有答卷不扣新建答卷额度；交卷、重复提交、成绩读取不访问限流桶。没有按联系方式的人数限制或累计总次数限制。

请求额度在身份业务事务前提交，不因联系方式不匹配而回滚。新记录额度与创建记录处于同一事务；创建失败一起回滚。多个桶按HMAC键排序加锁，全部够用时才一起扣减。时钟回退不会补充额度。只保存用途命名空间、HMAC键、余额和时间，不保存原始IP、Cookie或身份字段。日志不输出键、Cookie和身份值。

## 可信代理

默认不信任转发头，使用实际连接地址。生产设置 `QUIZ_TRUSTED_PROXY_CIDRS` 为实际代理连接来源的明确CIDR；香港Docker部署应在发布时读取Web入口网络网关并配置其精确地址。不得使用 `0.0.0.0/0` 或 `::/0`。

只有可信来源的 `X-Real-IP` 被接受，其他请求头被忽略；可信代理未提供有效地址时登记返回503。Nginx必须覆盖客户端自带的 `X-Real-IP` 和 `X-Forwarded-For`。IPv4按单地址归并，IPv6按 /64 归并，IPv4映射地址归为IPv4。

原生Caddy部署须覆盖 `X-Real-IP` 并配置回环代理地址，不能只信任任意客户端请求头。开发直连模式保留空列表。

## Nginx发布模板

`deploy/nginx/` 包含本站虚拟主机、共享限流区、白名单位置和代理头模板。发布时替换站点、证书、日志、静态目录、snippets目录和上游端口占位符；替换完成后必须先执行 `nginx -t`。不得把未替换模板直接装入线上，也不得将本站规则套到其他虚拟主机。

| 请求组 | 单IP速率 / burst | 站点速率 / burst |
| --- | --- | --- |
| 登记/恢复 | 10/s / 100 | 20/s / 200 |
| 开卷 | 20/s / 100 | 40/s / 200 |
| 交卷 | 50/s / 200 | 100/s / 400 |
| 页面/读取/授权题图 | 100/s / 1,000 | 200/s / 2,000 |
| 退出参与者会话 | 10/s / 50 | 20/s / 100 |
| 健康检查 | 5/s / 50 | 20/s / 100 |

均使用 `nodelay`，超额返回JSON 429及3秒等待提示。登记与DELETE通过空限流键分流，不互相扣减。静态文件独立服务，目录列表关闭；未知路径不进入Django。公网后台与直接题库媒体继续不可访问，私密管理入口不套用此策略。

保持原有五字段访问日志格式；限流拒绝的Nginx错误日志级别为notice，低于本站warn门槛，避免新增含客户端IP的拒绝日志。429数量仍可从访问状态码统计。

## 清理与回退

闲置一小时的桶可由 `python manage.py prune_rate_limit_buckets` 删除，每次最多10批、每批1,000条。删除时重新检查到期条件，避免误删并发刷新后的桶。

原生部署使用 `nihongo-quiz-prune-rate-limits.timer`；香港Docker部署使用 `nihongo-quiz-hk-prune-rate-limits.timer`。周期15分钟，任务只处理限流桶。

回退旧应用前停止新增清理timer/service，恢复应用、静态资源及本站Nginx配置。限流表保留，避免紧急删表或误恢复整个数据库。已有身份、答卷和成绩不因回退改变。参数调整需要重新验证50人同IP流程，不自动放宽阈值。
