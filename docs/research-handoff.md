# 往届答题包研究交接

最后更新：2026-08-25

## 已验证事实

往届包是 Django 4.2.4 应用，使用 Excel 题库和 CSV 成绩表。浏览器流程包括填写身份资料、选择七个板块之一、随机生成 15 题、进行 5 分钟倒计时、提交并保存分类最高分。

题库共有 378 题，包含选择题和题图。旧实现按 Excel 物理行号划分板块，修改行序会导致串题或越界。旧 `models.py` 为空，参与者与成绩不进入数据库。

单人流程和七个板块都能运行。24 路并发提交测试中，所有请求返回 HTTP 200，但只有一次成绩更新保留，其余 23 次被 CSV 整表覆盖吞掉。旧实现因此不能直接用于多人现场活动。

旧配置还存在硬编码密钥、调试模式、公网开发服务器、动态写模板、客户端计时可绕过、题号可篡改、身份资料进入文件名、无自动化测试等问题。

## 迁移结论

- 新项目采用干净 Django 基线，不把旧源码直接当作正式实现。
- 参与者、身份资料、答题记录和分类最高分进入 PostgreSQL，并用事务或原子更新保护。
- 服务端保存本次抽题和截止时间，提交时不信任浏览器提供的题号、板块和计时。
- Excel 继续作为题库编辑入口，但导入逻辑使用稳定题号和显式板块字段。
- 历史参与者数据不迁移。新部署从空数据集开始。
- 现役题库、答案和未审查素材始终保持私密。

## 托管结论

学校 Vlab 虚拟机资源足够用于私有预发布，但当前网络政策不提供公网端口映射，因此不作为参与者入口。朋友提供的校内服务器和 `mmdustc.top` 子域名是当前公开部署候选，仍需确认公网 80/443、隔离、备份、备案接入关系和运维联系人。

GitHub Pages 只能承载静态内容，不能运行 Django 后端。未来 GitHub Organization 负责源码协作，不共享个人账号。
